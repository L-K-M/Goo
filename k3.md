## Bugs

- **K3-1** 🐞 **Top rail overflows on ≤360dp-wide screens** (high confidence).
  `TopRail` (EditorScreen.kt:503) packs back + 6 candy buttons at 48dp minimum
  each plus 6dp spacing: ≈374dp of content. Samsung S-series and many A-series
  phones are 360dp wide; `Arrangement.SpaceBetween` can't shrink them, so the
  trailing (export!) button is pushed off the right edge. **Fix: scrollable
  controls row. → PR**

- **K3-2** 🐞 **History actions can orphan live-stroke pixels** (high
  confidence in the mechanism, narrow reachability). `undo()`, `redo()`,
  `reset()` (EditorViewModel.kt:388-407) call `discardLiveStroke()` and then
  return null when the log op is a no-op — and the screen only rebuilds the
  field on a non-null result. A discarded stroke's stamps are already on the
  GPU field, so a null return leaves pixels on screen that the document (and
  undo, and export) knows nothing about. Reachable today: levers-only document
  (`canReset = true` with empty log) + second finger confirms Reset while the
  first finger is mid-stroke. **Fix: force a rebuild whenever a live stroke
  was discarded. → PR**

- **K3-3** 🐞 **Tapping a pumped tool does nothing** (high confidence).
  Grow/Shrink/Smooth/UnGoo emit their first stamp on the 16 ms pump tick
  (EditorViewModel.kt:321); a quick tap starts and ends the stroke between
  ticks, so zero stamps — the tool appears dead. KPT Goo applied one shot on
  click. **Fix: emit the first stamp in `beginStroke`. → PR**

- **K3-4** 🐞 **Movie export does disk I/O on the main thread** (high
  confidence, low impact). `MovieSaver.createWorkFile()` (mkdirs + delete of
  predecessors) is called synchronously from `exportGoovie()`
  (EditorViewModel.kt:534), invoked from the UI. **Fix: suspend + IO
  dispatcher. → PR**

- **K3-5** ⚠️ **HEIC photos fail on API 26–27** ("could not open image" pane).
  `BitmapFactory` only decodes HEIC on 28+, and the system photo picker hands
  out HEIC on modern galleries. minSdk 26 means 26/27 users picking a HEIC get
  the error pane. The failure is at least graceful. DEFERRED (document as
  known limitation; a fix means an ImageDecoder/decode fallback matrix for two
  API levels).

## General issues / hygiene

- **K3-6** 🔧 **Dead dependencies**: `datastore-preferences` (main;
  OnboardingPrefs uses plain SharedPreferences), `turbine` and
  `kotlinx-coroutines-test` (test; no imports anywhere). The backup-rule XMLs
  also include a `datastore` files path that doesn't exist. **Remove the three
  deps + unused catalog entries. → PR** (backup XMLs left alone: harmless,
  and the path will exist the day DataStore is actually adopted).

- **K3-7** ⚠️ **Stroke log and keyframes die with the process** (= REVIEW.md
  G-2, still the biggest product gap). The types are `@Serializable` and the
  session-file restore path already exists — the document just isn't written
  down. Losing 20 minutes of goo on a phone call is the app's worst possible
  surprise. DEFERRED (real feature: ProjectStore + restore UX) — top of
  ANALYSIS.md.

- **K3-8** 🔧 **Fusion photo B can never be removed, only swapped.** Once B is
  loaded there is no affordance to go back to a single-photo document; worse,
  with B "gone" mentally but the FUSE tool still selected, the user could
  paint an invisible mask (`u_hasB` gates the display, not the mask
  accumulation). **Fix: "Remove photo" chip next to "Swap photo"; clearing B
  also returns the tool to Smear. → PR**

## Performance

- **K3-9** ⚠️ **Pumped-tool log inflation** (= REVIEW.md G-6, plus one new
  observation). 60 stamps/s while held; undo/export replay is O(stamps). The
  new observation: **GOOvie playback hitches at segment boundaries** — a
  segment crossing mid-playback replays a whole stroke prefix on the GL thread
  (`materializeInto`, GlWarpRenderer.kt:457) inside the frame loop, so heavy
  logs stutter the animation exactly at each keyframe. Field checkpoints
  (G-6's fix) would cure both. DEFERRED (tracked; needs device profiling
  first per REVIEW.md policy).

- **K3-10** ⚠️ **`renderMovie` is one monolithic GL runnable** (= REVIEW.md
  G-7). Tracked, still correct; the chunked-session fix matters before longer
  movies are promoted. DEFERRED.

- **K3-11** 🔧 **Preview decode is always 2048** (`ImageLoader.PREVIEW_MAX_DIM`)
  regardless of view size or GPU class. On a small/low-end device a ~1024
  preview would halve texture upload and warp-pass fill with no visible
  difference. DEFERRED (idea; needs a device-class heuristic, easy to get
  wrong).

## Missing features (vs PLAN.md's own promises)

- **K3-12** 🔧 **Bundled sample images** — PLAN §6.1: "sample images to play
  with instantly". Home has none; the picker is the only door. **Implement:
  two procedurally generated, provenance-clean samples + generator script +
  a sample row on Home. → PR**

- **K3-13** 🔧 **No brush cursor** — you paint blind: neither size nor
  position feedback until the warp appears. KPT Goo drew a brush ring; on a
  finger-occluded phone screen it's even more valuable. **Implement: a ring
  under the finger during strokes, radius = live brush radius. → PR**
  (Note: upstream PR #11 landed mid-review and covers the *slider-adjust*
  case with a centered falloff preview; this entry covers the *painting*
  case, ring styled to match #11's.)

- **K3-14** 🔧 **Keyframe capture is locked inside GOOvie mode** — the KPT
  loop is *goo, punch, goo, punch*; here you must open the strip (which
  pauses editing) to punch. Pins are stroke counts, so capturing from the
  brush rail is safe and keeps the flow alive. **Implement: a "Punch" chip on
  the brush rail that captures without opening the strip. → PR**

- **K3-15** ✨ **Settings screen** (PLAN §6.4): haptics/sound toggles, export
  defaults. Only About exists; haptics are always on. DEFERRED (small but
  plumbing-heavy: a CompositionLocal for haptics through every candy
  control).

- **K3-16** ✨ **Sounds** — PLAN §2 promises "squishy sounds", roadmap #6 said
  "optional sounds"; nothing landed. Delightful version: procedurally
  synthesized squishes (PCM, no assets, no network). Depends on K3-15 for the
  toggle. DEFERRED.

- **K3-17** ✨ **GIF export** — ~~explicitly deferred by PLAN §4.1 ("GIF
  secondary... deferred to the polish pass"). DEFERRED (palette encoder is a
  chunk of work; MP4 covers the share case)~~ — **DONE (post-v1 #16: pure-JVM
  median-cut palette + GIF89a LZW encoder, Netscape loop block, fed by an
  offscreen readback of the MP4 path's tween walk; shipped alongside the
  ½×–4× export speed control).** Removed from the backlog.
